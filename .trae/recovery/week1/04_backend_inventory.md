# Week 1 — Backend Module Inventory

**Inventory Date:** 2026-09-14

## Executive Summary

This inventory catalogs **126 logical backend modules** across the primary FastAPI application, Express API Server artifact, data/RAG layer, drafting engine, agents, container infrastructure, and test suites of the legal-luminaire repository. Of these, **96 are categorized active**, **11 are duplicated** (overlapping or parallel implementations), **3 are deprecated/unclear in status**, **7 are broken or physically missing**, and **9 are unclear** in their exact role or active state based on path-level inspection and import checks. The top-3 duplicates/gaps observed are:

1. **Dual document_store implementations** — `rag/document_store.py` (original) and `rag/optimized_document_store.py` (patch-level variant) both exist with divergent APIs; no explicit routing gate in `main.py` selects between them, causing potential silent import-path inconsistency depending on which agent calls `from rag.document_store` vs direct import of the optimized variant.

2. **Dual backend servers with feature overlap** — The primary FastAPI backend (`artifacts/legal-luminaire/backend`) and the parallel Express TypeScript API Server (`artifacts/api-server/`) both expose overlapping `/cases`, `/drafts`, `/health` routes with divergent business logic; no upstream router or reverse-proxy dispatches between them, meaning the frontend has two independent backend endpoints that could serve inconsistent states (see `api-client.ts` vs `lib/api-client-react` in frontend).

3. **Uploaded Cases gap TC-02..TC-21** — Only 6 of 26 promised TC case directories physically exist on disk (TC-01, TC-22..TC-26), yet `scripts/seed_26_cases.py` and `api/routes_cases.py` enumerate 26 case IDs, causing 20 HTTP 404 paths in the case-browser UI; additionally, 4 imaginary case directories exist with inconsistent naming (imaginary_case_01/03/04/05, skipping 02), creating 1 additional orphan namespace collision risk.
