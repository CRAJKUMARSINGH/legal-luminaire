**COMPREHENSIVE LAUNCH-READY TASK FOR CODEX**  
**Repo:** https://github.com/CRAJKUMARSINGH/legal-luminaire  
**Goal:** Take the current evidence-first legal workbench (multi-agent drafted, strong Fact-Fit Gate + verification engine already in place, ~349–388 tests, 26 synthetic cases) to a **production-grade, court-ready launch state** in one coherent, non-piecemeal pass.

### Context & Constraints
- **Product:** India’s citation-safe, bilingual (EN/HI) legal research & litigation intelligence workbench. Core promise: **Fact-Fit Gate** (5-tier: COURT_SAFE → FATAL_ERROR) that **physically blocks** PENDING / FATAL_ERROR citations from any court-ready export. Deterministic deadline engine (CrPC), grounded copilot, PII redaction, local-first privacy, 26 synthetic demo cases (Hemraj stadium collapse etc.).
- **Stack:** pnpm monorepo · React 19 + TypeScript + Vite frontend (`artifacts/legal-luminaire`) · FastAPI + Python backend (CrewAI / LangChain / ChromaDB multi-agent) · Vitest + pytest · Netlify / Docker / Vercel targets.
- **Current strengths:** Strong accuracy posture, verification engine, bilingual drafting, demo mode works without backend, high test count.
- **Known pain points (from docs):** Navigation overload (40+ items), empty states, missing onboarding, incomplete loading states, scattered code, feature-flag sprawl, some legacy routes, incomplete CI/ops polish, self-assessment ~8.3/10.

**Non-negotiable rules for this task:**
1. **Never weaken the Fact-Fit Gate or Verification Engine.** PENDING / FATAL_ERROR must remain hard-blocked from export. Adversarial probes must continue to pass.
2. All synthetic data must stay clearly labelled. Never introduce real client data.
3. Fail closed on privacy (PII redaction, no leakage of case content, keys, or unverified material).
4. Frontend must remain fully usable in pure demo / offline mode (no backend required for core flows).
5. Prefer surgical, well-tested changes. Document everything in a single root `LAUNCH_HARDENING_REPORT.md`.
6. Keep bilingual (EN/HI) depth and legal terminology accuracy.
7. All changes must pass typecheck, lint, frontend tests, backend tests, and a defined launch gate.
